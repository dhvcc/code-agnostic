# UX review 2026-05-31 08:32

Review lens: `code-agnostic` should help users understand, migrate, validate, preview, apply, and recover one source of truth across Codex, Cursor, and OpenCode. Baseline was `automation/integration` at the start of cycle `2026-05-31-0700`; no non-deferred alpha blockers were open.

## Exercised flows

- Empty-state `validate`, `status`, `apps list`, `plan`, `skills list`, and `restore` in an isolated home.
- Scoped app flow with `apps enable -a codex`, `plan -a codex`, `status -a codex`, and `apply -a codex`.
- Invalid source flow with bad `config/mcp.base.json`.
- Global and workspace skill listing with `skills list` and `skills list -w team`.
- Docs review across README, compiler docs, and the prior UX review note.

## Recommendations

- Patch: Keep plan/apply next steps truthful for the current target and command. This branch makes disabled scoped plans show exact enable/plan/apply commands, enabled scoped plans show the exact apply command, no-change plans point to status, and apply output no longer repeats plan next-step guidance. No open blocker ID exists; this follows the prior target-aware next-step handoff.
- Patch: Guard interactive import in non-interactive terminals. `import plan -a codex -i` can enter a full-screen picker without a clean automation fallback; fail fast with an actionable message or provide an explicit non-interactive selection mode. No open blocker ID exists.
- Patch: Keep validation and recovery visible in the primary docs. This branch adds `validate` to the quick path and documents `restore` as the recovery command after managed outputs need repair.
- Minor: Improve skill discoverability in the CLI. `skills list` still shows only a name, so users cannot see scope, source format, or generated target expectations. Add scope/source/format columns and make the empty state point to the global or workspace source directory.
- Minor: Add a first-class skill install or scaffold workflow. Manual copying into the source tree works, but users expect `code-agnostic skills install` or `skills add` to make local skill management part of the normal source-of-truth workflow.
- Major: Design the full skill lifecycle around global vs workspace-local behavior. Users need one coherent workflow for where a skill lives, how it is validated, how it propagates to Codex/Cursor/OpenCode, how `status` proves it is synced, and how to recover if generated outputs are wrong.
