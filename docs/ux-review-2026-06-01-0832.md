## What changed in this branch

- Patch: aligned the README's first source-tree example with the preferred bundle source format (`meta.yaml` plus `prompt.md`) while explicitly preserving legacy single-file support for migration.
- Minor: made `code-agnostic skills list` show scope, source format, and source directory so users can distinguish global skills from workspace-local skills and legacy `SKILL.md` sources from bundle sources.

## Recommendations

- Patch: land or otherwise reconcile the same-cycle ecosystem branch `origin/ecosystem/2026-06-01-codex-user-skills-dir` before release. It handles current Codex global skill path drift (`.agents/skills` instead of `.codex/skills`); this UX review does not duplicate that code-path change.
- Patch: add a non-interactive guard for `import plan -i` / `import apply -i`. If stdin/stdout is not interactive, the command should fail with a short message that suggests dropping `-i` or running in a real terminal.
- Minor: add next-step guidance to import output. `import plan` should point to the matching `import apply` command, and conflict/error output should name the conflict policy flags users can choose from.
- Minor: make `workspaces remove` safer by wording it as unregistering a workspace, or add an explicit `--delete-config` path for removing `~/.config/code-agnostic/workspaces/<name>`. Today the command removes the index entry but leaves workspace-local config that can be resurrected by re-adding the same name.
- Minor: add `status --fail-on-drift` for CI and scripted checks. Current `status` exits nonzero for errors only, which is reasonable for human inspection but easy to misuse as a drift gate.
- Major: design the full skill lifecycle instead of adding isolated commands. Users need `skills init`, `skills install`, `skills move --workspace/--global`, `skills list --all`, and clear overwrite/conflict behavior that routes every change through the source of truth and normal `plan` / `apply` flow.

## Product read

The core promise is now mostly understandable: source config lives under `~/.config/code-agnostic`, users preview with `plan`, then apply generated app-specific output. The weakest remaining UX area is skill management. The CLI can sync skills, but users still have to know where to place local skill files, how workspace-local skills interact with global skills, and how to move or install a skill without bypassing the source of truth.

Recovery is present but still terse. `restore` exists and the reliability run hardened it, but the product should eventually explain what revision is restored and whether any targets were skipped or preserved.
