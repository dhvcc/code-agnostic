# UX review 2026-05-30 15:18

Baseline note as of 2026-05-31: this review was written against an older baseline. The plan/status error signaling findings are covered by integrated ABLK-001 and ABLK-002, and the workspace-only Codex apply/status findings are covered by integrated ABLK-007. Keep the remaining skill discoverability, recovery, import, and product E2E recommendations as follow-up context, but do not treat the fixed blocker bullets below as current findings.

Review lens: `code-agnostic` should feel like a trustworthy migration and sync CLI for one source of truth across Codex, Cursor, and OpenCode. The current baseline helps users preview and apply config, but several flows still weaken trust when the rendered CLI state conflicts with exit codes, status, or generated target paths.

## Exercised flows

- Empty-state `validate`, `status`, `apps list`, `plan`, `skills list`, and `restore --help` in an isolated home.
- Enabled-app `plan -a codex`, `status -a codex`, `apply -a codex`, and `import plan -a codex`.
- Workspace-scoped Codex skill flow with `skills list -w team`, `plan -a codex`, `apply -a codex`, and `status -a codex`.

## Recommendations

- Patch: Make plan errors control the process result consistently. `plan -a codex` rendered `Missing required config file: ~/.config/code-agnostic/config/mcp.base.json` but exited `0`, which makes scripts and users trust the wrong signal.
- Patch: Make `status` surface source and planning errors. With Codex enabled and no `mcp.base.json`, `status -a codex` reported `synced / in sync` while `apply -a codex` correctly aborted.
- Patch: Do not require unrelated global MCP source files for workspace-only skill or agent sync. A workspace-only Codex skill plan produced valid workspace actions but was blocked by missing global `config/mcp.base.json`.
- Patch: Align Codex workspace skill status with the actual generated target. Apply writes workspace skills to `.agents/skills`, but status reports `missing or mismatched codex skills link`, which makes a successful apply look untrustworthy.
- Patch: Keep all command examples aligned with named-flag CLI conventions. This branch fixes the plan next-step panel from positional `<app>` commands to `-a <app>` commands.
- Patch: Remove stale absolute documentation links. This branch replaces local `llm-sync` paths with repo-relative compiler docs links.
- Minor: Improve skill discoverability. `skills list` only shows names, so users cannot see global vs workspace scope, source format, or generated targets. Add scope/source/format columns and a direct hint for where new skills should be installed.
- Minor: Add a first-class skill install or scaffold path. The README documents manual copying and a planned `skills install`; the product should make local skill management part of the normal source-of-truth workflow.
- Minor: Make recovery visible after risky operations. `restore` exists, but apply output does not show the created revision or the exact restore command users should run if an apply is wrong.
- Minor: Guard interactive import in non-interactive terminals. `import plan -a codex -i` opened a full-screen selector in automation without a clean fallback; fail with an actionable message or provide a non-interactive selection mode when stdin is not a TTY.
- Major: Add real app-ingestion product E2E. Filesystem assertions prove generated files exist, but alpha confidence needs evidence that Codex, Cursor, and OpenCode actually load the generated MCP, skills, agents, and workspace instructions.
- Major: Settle the workspace skill mental model. Users expect a local skill added through `code-agnostic` to have a clear source, scope, generated target, status contract, and recovery path. Today those pieces exist in different places but do not read as one workflow.
